# Language selector implementation plan

Status: implementation plan for [issue #89](https://github.com/thecodingbob/ctr-native/issues/89). The detailed file syntax and remaining technical decisions are provisional. No game content from retail discs will be distributed.

## Goals

- Add System > Language with separate Audio and Text rows, each opening a dynamically populated picker like the Controls device picker.
- Default both selections to English and apply changes immediately. Use only English from the base image; ignore its other language records. Discover additional available languages from an optional European image, and custom languages or overrides from `assets`.
- Resolve content per language and per resource: base English, then European disc content where available, then matching asset overrides. Asset files can replace individual existing strings or audio resources. Fork-only strings come exclusively from assets.
- Move the fork's custom English strings into the agreed asset format, and document how to create translations and audio overrides.
- Evaluate disc-backed loading against extracting resources ahead of time, with measurements, before deciding the production approach.

## Current starting points

- `game/MAIN/MainMain.c` loads English bigfile slot 1 at startup. `game/LOAD/LOAD_Assets.c` loads a language file into the game's memory arena and fixes up its string pointers. The comment there lists candidate retail slots, not a verified inventory for each disc.
- `game/CDSYS.c` contains retail XA language selection, but native startup calls `CDSYS_Init(0)`, so `CDSYS_SetXAToLang` returns without changing playback. The native path in `platform/native_audio.c` independently hardcodes `XA/ENG.XNF` and `XA/ENG/{EXTRA,GAME}`; it must be changed for language switching. Audio coverage, other audio paths, and any language-dependent video or subtitles must be inventoried before promising coverage.
- `platform/native_disc_image.c` assumes one NTSC-U `ctr-u.bin`; `platform/native_assets.c` indexes extracted assets and gives them precedence over disc files. A second disc must not silently replace unrelated base-game content.
- `game/230/MM_ConfigMenu.c` owns System navigation; `game/230/MM_ControlsConfig.c` contains the existing device picker. Configuration is table-driven in `platform/native_config.c`.
- Initial ISO directory inspection found `assets/ctr-u.bin` (volume `SCUS-94426`) and `assets/ctr-e.bin` (root executable `SCES_021.05`). Both have `BIGFILE.BIG` and an XA directory, but their bigfiles have different LBAs and sizes. The US XA directory contains `ENG` and `ENG.XNF`; the European directory contains `DCH`, `ENG`, `FRN`, `GRM`, `ITL` and `SPN`, each with an XNF, plus music. Directory presence alone does not establish usable text or voice coverage. European language slots, individual XA files, compatibility and source-specific sector addressing still need verification.
- Direct inspection of the supplied images found 608 US and 723 European BIGFILE directory entries. Both have eight nonempty records at `BI_LANGUAGEFILE` (index 234); ignore the US records other than English, and do not assume European records are usable just because they exist. The European records in these images range from 11,820 to 16,064 bytes, below the current 16,132-byte language buffer, but loaders must check sizes rather than assume other images fit. The records have different sector offsets between the two images.
- Comparing the English US and PAL tables shows three PAL-only controller strings inserted at US indices 547, 548 and 553. PAL text must be remapped to US indices, not installed unchanged. A direct reader probe against the supplied European image validated text records and found voice metadata and `GAME/S00.XA` for French, German, Italian, Spanish and Dutch; live playback and layout still need in-game validation.
- XA indices are track IDs within an XNF category, not global audio IDs. The XNF entry resolves each ID to an XA file number, channel and sector count. For the supplied US and PAL English XNFs respectively, music has 13/13 tracks, EXTRA has 87/81 and GAME has 314/264. Track counts alone do not imply identical ordering.
- Comparing the executable voice tables shows 16 character blocks in both regions. Each US block contains eight two-clip sets followed by three one-clip sets (19 IDs); each PAL block contains only the first eight two-clip sets (16 IDs). Corresponding positions in the first eight sets have the same role, including the duplicated IDs in character 10. The US `voiceID` event-to-set table maps events 21–23 to set 8; the PAL table maps these events to set 0 instead. Thus the PAL executable substitutes the first two-clip set for those events rather than supplying PAL equivalents of the US one-clip sets. Boss-race code may also select sets 4–7.
- Immediate impact reactions and the voice-volume preview are not XA: both use `OtherFX_Play` and sampled SPU audio from `SOUNDS/KART.HWL`. The supplied PAL HWL has 428 OtherFX entries versus 258 in the US HWL. Its language blocks begin at OtherFX 224 (English), 258 (French), 292 (German), 326 (Italian), 360 (Spanish) and 394 (Dutch), with 34 entries per block; the first 32 correspond to US OtherFX 28–59. Direct reads validated all 160 non-English samples. Localized samples are loaded into the existing level-local SPU cache, invalidated on bank teardown and checkpoint restore, and selected independently from text. In-game playback and loading latency remain to be verified.
- Implementation order: first support direct, independently addressed reads from the optional European image and verify actual retail text and voice resources and immediate switching. Defer TOML, custom packs and overrides until the disc-backed path is understood and tested. Measure runtime reads before deciding whether extraction is needed.

## Proposed resource contract (to agree)

### Agreed text catalog structure

Use `assets/text/<language-id>/language.toml` for the stable language ID and display name, with separate optional `retail.toml` and `expanded.toml` catalogs. Retail keys refer to existing retail string identifiers; Expanded keys identify strings added by this fork. Confirm and document the exact key syntax and mapping before implementation. Ship English Expanded strings without distributing retail disc content. Catalogs may be partial, and a language may provide either or both catalogs. Migrate all player-facing Expanded strings to TOML.

The split identifies the origin of a key, not the game mode or screen where it is used. If Chaos and a retail screen request the same retail key, they share its translation. A context-specific wording requires a separate Expanded key and an explicit change to that consumer; any fallback to a retail key must be defined explicitly. Do not split retail catalogs by game mode for now.

Add an option in the Language menu to enable optional retail TOML overrides; default it to disabled. When enabled, resolve each retail string from a valid selected-language override, then the selected European disc string if available, then base English. When disabled, skip retail TOML overrides. Expanded catalogs are not controlled by this option: resolve a valid selected-language entry, then the shipped English Expanded catalog. Define recovery behavior if the shipped catalog is missing or invalid without retaining a second catalog of Expanded strings in code.

Add an “Extract translation files” action in the Language menu. It exports only retail text from the user's available source data as editable TOML, providing a starting point for overrides. Expanded strings are already supplied as TOML and must not be extracted. Export source text before applying retail overrides, with proper encoding and TOML escaping; never overwrite existing files silently. Define the language selection, destination, conflict handling, error reporting, and behavior for unavailable source languages before implementation. Do not ship extracted proprietary retail text.

The catalogs are UTF-8, but the game font currently consumes its own byte encoding and control codes. Define and test conversion, unsupported-character handling, formatting tokens and placeholders before accepting translations. Invalid content must not corrupt the active table; report unknown or invalid entries and fall back per string. Define safe pointer lifetimes across language switches, arena resets and checkpoint restores.

Provide one centralized string resolver for retail and Expanded keys. All migrated consumers request strings through this interface; keep source selection, optional retail overrides, fallback and invalid-key handling in the resolver rather than duplicating them across menus or game modes. On load or language change, parse and validate the relevant catalogs and build a resolved in-memory table so ordinary lookups do not perform file I/O or TOML parsing. Prepare replacements before publishing them and define pointer ownership and checkpoint behavior before freeing prior tables. Inventory existing direct retail table accesses and migrate them coherently without breaking consumers that require the resident layout.

Text and audio availability remain independent. Audio pack structure, identifiers, formats and override semantics are deferred; this phase is limited to text.

Use TOML for editable text catalogs and the selected [tomlc17](https://github.com/cktan/tomlc17) parser. Release R261003 is vendored at commit `8d3766ddafa6515417f4885ae6878ef69fac401e` with its license; upstream specifies TOML 1.1. The parser is built separately from the game unity unit. Focused tests pass on MSVC x86 and MinGW i686 for malformed input, UTF-8 validation, embedded NUL and copying strings before freeing the result. UTF-8 checking is off by default and must be enabled by catalog loading. The MinGW game builds; the MSVC game build currently fails in unrelated existing game code, so the full MSVC integration remains unverified.

Discover text and audio availability independently from valid resources, not merely from a directory name. Merge sources deterministically for each selected language. Missing retail resources and fork-only translations fall back to English, including for partial packs. Validate invalid files and unknown keys without corrupting the resident language table. Keep override buffers alive as long as game pointers can reference them, and account for arena resets and checkpoints.

## Work breakdown

1. Inspect `assets/ctr-e.bin`; compare its ISO directory, bigfile language records and XA metadata to the base disc. Determine actual languages and content coverage, distinguish text slots from XA language IDs, and check image validation and raw-sector assumptions. Inventory fork-authored strings and text/font limitations, including supported accented characters and formatting tokens.
2. Trace text loads, XA and other voice playback, CD addressing, asset overrides, memory ownership, checkpoints and configuration/menu lifecycle. Design immediate reload and stream switching, including interactions with active streams, save states and extracted base assets.
3. Agree on the asset contract and fallback semantics; document discovery, keys, file encoding, text escaping/format placeholders, audio format and examples, plus error handling and content ownership. Provide a shipped English file for fork strings without including proprietary retail content.
4. Implement a source-aware language inventory and separate optional European disc access, maintaining existing base disc and extracted asset behavior. Implement deterministic overlays, safe resource lifetime and fallback; avoid treating all European disc files as base-game replacements.
5. Add persistent independent audio/text selections and dynamic pickers under System > Language. Apply confirmed changes immediately; handle missing previously selected languages, empty or invalid packs, navigation, scrolling and cancellation. Update the default configuration and user documentation.
6. Migrate fork strings and their consumers to the asset-backed catalog, including menu labels and any non-retail strings identified in the inventory. Verify placeholders, fonts, length and layout; do not assume every hard-coded string is player-facing.
7. Add focused tests for discovery, precedence, partial overrides, malformed files, persistence and fallback, plus integration coverage for both discs and individual audio overrides. Manually verify menu behavior and audio/text independently across relevant game states, with and without European disc and extracted assets.

## Performance decision gate

Compare reading only requested language resources directly from the images against one-time extraction into the proposed format. Measure startup and language-switch latency, race/menu transitions, audio interruptions, memory and disk usage, and behavior on representative storage. Include cold and warm runs and validate playback correctness, not just throughput. Consider cache invalidation and user-supplied disc ownership. Prefer runtime disc access if measured costs are acceptable; otherwise document an extraction/cache strategy and its invalidation. No performance conclusion is claimed yet.
